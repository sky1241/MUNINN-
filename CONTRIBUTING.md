# Contributing to MUNINN

Thanks for considering a contribution. This document covers what we need from
PRs and how to set up a working dev environment.

## Quick Setup

```bash
git clone https://github.com/sky1241/MUNINN-.git
cd MUNINN-
python3 -m venv .venv && source .venv/bin/activate
pip install -c constraints.txt -e '.[all]'
pip install -c constraints.txt pre-commit
pre-commit install
pytest tests/ -q
```

If pytest is green and `pre-commit run --all-files` passes, you have a working
environment.

## What kind of contributions are welcome

- **Bug fixes** — open an issue first describing the bug; include verbatim
  command output.
- **Test coverage** — additional tests for engine/core/ are always welcome.
- **Documentation** — typo fixes, clearer prose, examples.
- **Performance** — with a benchmark before/after.
- **New features** — open an issue first to discuss; large features without
  prior agreement may not be merged.

## Pull Request checklist

- [ ] Tests added or updated for new behavior
- [ ] `pytest tests/ -q` passes locally
- [ ] `pre-commit run --all-files` passes
- [ ] CHANGELOG.md updated with a Keep-a-Changelog entry under `[Unreleased]`
- [ ] Public API changes are reflected in README.md / docs/
- [ ] No secrets, API keys, or `.env` content added (the secret scrubber should
      catch this, but verify)

## Coding conventions

- Python 3.13 only. We use modern syntax (`X | None`, `list[int]`, structural
  pattern matching where it helps).
- Type hints on every public function. Internal helpers may omit if local.
- Docstrings on public functions explain *why*, not *what*.
- `_log = logging.getLogger("muninn.<module>")` over `print()` in production
  code. CLI entry points may print.
- Narrow `except` clauses. If you catch `Exception`, you must either re-raise
  or log with context. No silent `except: pass`.
- Tests live under `tests/`. Prefer property-based tests
  (`tests/test_props_*.py`) for engine modules.

## Architecture notes

- `engine/core/` is the source of truth. `muninn/` re-exports for convenience.
- The mycelium DB schema is in `engine/core/mycelium_db.py`. Migrations
  require a `scripts/migrate_*.py`.
- Hooks are auto-generated by `muninn install` — never edit
  `.claude/hooks/*.py` by hand; modify the template in
  `engine/core/muninn_install.py` and re-run install.
- Sync semantics are CRDT (MAX(count), MIN(first_seen), MAX(last_seen)).

## Reporting issues

- One bug per issue.
- Include `muninn doctor` output if relevant.
- For security issues, see [SECURITY.md](SECURITY.md) — **do not open a public
  issue**.

## Code of Conduct

Be respectful. Disagree with ideas, not people. No personal attacks.
